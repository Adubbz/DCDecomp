# CBound layout and virtual interface

The promoted `CBound::Sizeof` body belongs to the current upstream `dispctrl`
unit. Its shared type is owned by `include/bound.hpp`. The integration owner
supplied this contract separately from the isolated five-function dispctrl port.

Dayuppy's `include/cloth.h` supplies the candidate layout. Retail evidence:

- `__ct__6CBoundFfff` stores the vtable address at object offset 0x128 and
  extents at 0x10/0x14/0x18, their reciprocals at 0x20/0x24/0x28.
- `Sizeof__6CBoundFv` returns 0x130. Retail ELF symbol size is 0xC;
  the next-symbol interval is 0x10. Its binding is MWCC processor-specific 13.
- Retail data at `__vt__6CBound` (0x2A1380) is four words:
  `0, 0, 0x13DE90, 0x13D250`. Sizeof is the first virtual, InCheck the second.
  InCheck returns integer 0 or 1, and its retail size is 0x268.
- InCheck transforms a point with the inverse matrix at 0x80, compares the
  extents, scales by their reciprocals, then applies the matrix at 0x40 and
  center at 0xC0 to its output contact point.
- InitParam clears next at 0x00 and the unidentified word at 0x04; initializes
  friction at 0x30, frame pointers at 0xE4/0xE8, position/from/to at
  0xC0/0xF0/0x100, and distance scales at 0x120/0x124.
- ChangeDir copies vectors into 0xF0/0x100/0x110. SetDir uses the direction
  at 0xD0. The frame-taking overload stores update state at 0xE0 and frame0
  at 0xE4; UpDateDirPos also uses frame1 and both distance scales.
- CCloth::Step walks the pointer at 0x00, loads the virtual table at 0x128,
  calls InCheck, and reads the contact friction at 0x30.

The class includes the real vectors/matrices and native virtual methods;
`STATIC_ASSERT(sizeof(CBound) == 0x130)` checks the target ABI. Unidentified
storage stays opaque. No bound function body or vtable dump is replaced here.
The dispctrl worker separately checks `return sizeof(CBound)` against retail.

The same serialized pass removes the stale `@unknownret` from dataread's
existing compatible SearchPTS declaration. Its return is an archive pointer
or null, confirmed by both retail overloads. Owning overload documentation
is supplied by dispctrl; existing dataread consumers keep their declaration.
